# PLAN — Cycle Q: browse-on-dblclick + Create Schema form + column Type dropdown/defaults + requery bar above grid + AI sample data + keyword-table SQL fix + Postman Payload + AI Chat toolbar icon

## §1 Intent

Eight user features in this cycle (Q):

**(A) Double-click browse** (VI, translated): in the Schema Explorer's Tables list, clicking the
chevron (>) still expands columns as today, but **double-clicking the table row** should
immediately run the equivalent of `SELECT * FROM <schema>.<table>` and show the full content in
the results grid, where data is editable and savable (Commit back to the DB).

**(B) Create New Schema**: right-click a DB/connection node → "Create New Schema" menu item
opens a form popup "giống như new column/new table": Name field up top, generated
`CREATE SCHEMA <name>;` preview below, OK runs it, then tree refresh + reveal the new schema node.

**(C) Column Type dropdown + default auto-fill** (user-refined): the designer's column Type
field becomes a **dropdown with exactly 3 options — varchar (default selected), numeric,
boolean — no free text**. Default auto-filled `''` / `0` / `FALSE` per selected type, refreshed
when Type changes, user can override; edit-mode loads the existing type mapped to the nearest of
the 3 without corrupting the real type on the DDL wire.

**(D) Requery bar above the grid**: the WHERE + ORDER BY condition bar (inputs "e.g. id > 10" /
"e.g. created_at DESC" + Re-Run/Clear — TASK-504 controls) currently renders BELOW the table; it
must sit ABOVE the table, directly under the top control toolbar (footer stays at bottom).

**(E) AI-driven sample data**: right-click table → "Generate sample data" becomes AI-driven:
PK/identity column `id_<table_name>` and `created_at` are NEVER inserted (auto-generated); all
other column values are generated by the AI **work model** (`AiConfig.models.work`, NOT smart)
from the semantic meaning of table + column names (Vietnamese/English naming ok); output is
validated INSERT-only for that exact table, executed atomically, with a summary.

**(F) Keyword table names in executed SQL** (bug-level): `SELECT * FROM order;` fails when the
table lives in schema `public` and its name is a Postgres reserved keyword. Diagnose the actual
breakage (parser vs server), then fix via a pure, testable pre-execution transform that
qualifies unqualified table references with `public.` and double-quotes reserved-keyword
identifiers — only when they resolve to an actual table; never blind rewriting.

**(G) Postman Payload**: right-click table/view/routine → "Postman Payload" → clipboard gets a
JS object literal `{ schema, table: <name>, <col>: this.workingObj.<col>, … }` (key stays
`table` for all three kinds; columns from introspection).

**(H) AI Chat toolbar icon**: add `vsdb.aiChat` to the schema-tree view/title navigation menu,
directly after `vsdb.openAiSettings` (command already exists with `$(comment-discussion)` icon).

Success = all eight land in one cycle with repo patterns, scoped suites green, typecheck clean,
`npm run compile` builds all webview entries.

## §3 Approach

### A — browse on double-click

VS Code TreeView has no raw dblclick event; for an expandable TreeItem with a `command`, the
command fires on double-click/Enter while the chevron still single-click-expands. Table nodes
are `Collapsed` → exactly the requested UX; view nodes (`CollapsibleState.None`) fire on single
click — accepted trade-off (DataGrip-style preview; batched + cancellable).

`commandBrowseTableData` resolves node `meta` (`{connection, schema, objectName}` — same shape
`resolveTableNode` reads), aligns active connection (`await mgr.setActive(conn.id)` when the
node's conn differs; rejection → error message, no run), builds SQL, wraps as synthetic
`ParsedStatement {text, start: 0, end: text.length}`, drives the `runStatements` flow:
`setBusy(true) → runner.run([stmt], rs => panel.render(rs, header)) → render(results) → finally
setBusy(false)`. `ResultsPanel.render` re-derives `tableByStatement` via `parseFromClause`
(host-side truth; `readIdent` understands `"s"."t"` / `` `s`.`t` `` / `[s].[t]`), so edit+save
(PK lookup, ctid fallback, dialect quoting) works with zero panel changes.
`confirmDangerousStatements` skipped — a generated SELECT can never trip `guardTier`.
Rejected: exporting `runStatements` from extension.ts (ui importing entry file).

`buildBrowseSelect` (all 3 drivers — mysql/mssql route single SELECTs through streaming batched
handles): pg `"s"."t"` (`"` doubled), mysql backticks (doubled), mssql brackets (`]` doubled);
empty schema → unqualified; no trailing `;`. **No initial LIMIT** — QueryRunner batches (pg
cursor, mysql/mssql streaming), initial batch = `vsdb.batchSize` (default 500), Load More wired;
a hard LIMIT would break Load More. QueryRunner binds to ACTIVE → non-active node switches
active first. Copy stays on the context menu (replacement, not coexistence).

### B — Create Schema form: webview form, not InputBox

**Decision: webview form** (host `src/ui/schemaForm.ts` + entry `webview/schemaFormMain.ts` +
esbuild entry). The user anchored the UX to "giống như new column/new table" — styled field +
live SQL preview + OK/Cancel + Escape; an InputBox cannot render the preview. Cost verified:
NewTableForm is 246 host + 517 webview lines for a full designer; this is a strict single-field
subset (~120 / ~90). Webview bundles are self-contained (`newTableFormMain.ts` redeclares its
interfaces — no src imports), so no shared-type refactor; message unions stay inline in the host
module. esbuild: one `schemaFormConfig` block (per-form precedent).

`vsdb.createSchema` in `registerTableCommands` (`COMMAND_TITLE.createSchema = "Create Schema"`):
resolve target conn (node `meta.connection` → that conn; else `mgr.getActive()`; none → info),
`guardPostgres`, open `SchemaForm` with `listSchemaNames()` (via `adapter.listSchemas(true)`)
and `runDdl(sql, name)` → `adapter.runQuery(sql)`. OK → `tree.refresh()` →
`revealSchemaNode(treeView, conn, name)` → info message; error → `showErrorMessage("<Title>
failed: <msg>")`, no refresh (existing guard contract). Validation host-side in `postPreview`:
`/^[A-Za-z_][A-Za-z0-9_$]*$/`, length ≤ 63 (pg NAMEDATALEN), duplicate (case-insensitive)
against `listSchemaNames()`; invalid → error list + OK disabled. SQL via existing `alwaysQuote`:
`CREATE SCHEMA "name";`. DB-side duplicate race → runDdl error toast (pre-check is UX).
`findSchemaNode` mirrors `findTableNode` (`getAdapterFor` → `listSchemas(false)` → find → node
shape from `getSchemaNodesForConnection`); `revealSchemaNode` mirrors `revealTableNode`
(`_activeProvider`, swallows reveal throw).

### C — Type dropdown + default auto-fill (webview-local)

Verified locations: `webview/newTableFormMain.ts` edit pane renders `#colType` free-text (~L344)
and `#colDefault` (~L345); `commit()` (~L382-401) rebuilds the column from inputs; add-column
(~L196) creates `{name: col_N, type: "varchar"}` with NO default; modify-mode specs arrive fully
populated.

Dropdown: `<select id="colType">` with exactly varchar/numeric/boolean; new columns default
varchar. Defaults: pure `defaultColumnDefault(type)`: varchar→`''`, numeric→`0`, boolean→
`FALSE` (unknown→`""` safety branch). Tracking: module `Set<number>` of auto-filled column
indexes; add-column seeds + marks; type change on marked column recomputes and syncs the
`#colDefault` input + spec; manual default edit unmarks (override preserved); remove/up/down
remap; host-loaded columns never marked → modify-mode never injects.

**Edit-mode mapping (decided)**: `mapTypeToForm(realType)`: `char|text|uuid|json|xml`→varchar;
`int|serial|decimal|numeric|real|double|float|money`→numeric; `bool`→boolean; **else
(timestamp, date, jsonb, arrays, exotic) → varchar** (least-destructive textual placeholder).
**Real-type preservation rule**: track each column's `realType` (from host spec at init). On
`commit()`, `spec.columns[i].type` = realType when the dropdown still equals
`mapTypeToForm(realType)` (untouched) — so renaming a `timestamp` column emits `timestamp` and
`diffTable` produces no spurious ALTER. User actively changes the dropdown → selection becomes
the new intended type (realType updated). Consequence (accepted): flipping an exotic column's
dropdown genuinely changes its type — that is the intended edit.

Rejected: host-side injection (webview owns live edit state; host values overwritten by next
`commit()`, cannot see type-change events); `datalist` (still free text — violates 3-option
constraint); extending host `ColumnSpec` (wire-format change rippling into
diffTable/generateCreateTable for zero user value).

### E — AI-driven sample data (work model)

Current implementation (verified, `tableCommands.ts` L289-356): InputBox "Number of rows"
default 10, clamp 0..1000, `introspectTable` → `rowsToSpec` → deterministic
`generateSampleInserts` → untitled SQL doc; never executes. **Replacement** (same command id
`vsdb.generateSampleData`, same existing menu entry):

1. Guards: `resolveTableNode` → `guardPostgres` (unchanged contract).
2. AI config: `new AiConfigStore(context).loadConfig()` → null → info message + `executeCommand
   ("vsdb.openAiSettings")` (existing unconfigured pattern from `commandOpenAiChat`).
3. N: keep the InputBox UX (default 10); clamp **1..100** (AI cost cap — documented decision;
   the old 1000 cap is dropped for the AI path).
4. Columns: `introspectTable` (existing helper) → build insertable list: exclude `id_<table>`
   (case-insensitive) and `created_at`, exclude columns whose `column_default` contains
   `nextval` / identity. Empty list → info "nothing to generate" (e.g. only id + created_at).
5. Prompt: pure `buildSampleDataPrompt(schema, table, columns, n)` — table + column names with
   `format_type`, nullability, comments where present; instruct: N `INSERT INTO "schema"."table"
   (cols…) VALUES …;` statements, realistic values from the semantic meaning of Vietnamese or
   English names, no markdown fences, nothing except INSERT statements.
6. Call: `createProviderClient({ baseUrl, apiKey, method, timeoutMs }).complete({ modelId:
   cfg.models.work.modelId, messages: [{ role: "user", content: prompt }] })` — **work model
   only** (explicit requirement; `models.smart` never used here).
7. Validate: pure `parseInsertStatements(text, schema, table)` — strip fences; split statements
   (literal-aware splitter from `src/core/statementParser`); every non-empty statement must be
   `INSERT INTO` targeting exactly `alwaysQuote(schema).alwaysQuote(table)` (accepting the same
   quoting with doubled quotes). **Anything else → reject ALL, nothing executes** (inverted
   `run_sql` read-only guard philosophy: INSERT-only whitelist for this exact table). Column
   list must be a subset of the insertable columns.
8. Execute: single `adapter.runQuery(statements.join("\n"))` — node-postgres simple-query
   protocol runs multi-statement strings in an implicit transaction that rolls back on error →
   all-or-nothing without explicit BEGIN/COMMIT (documented; matches `runDdl` plumbing).
9. Summary: `showInformationMessage("VSDB: inserted <N> sample rows into <schema>.<table>")`;
   failure → `showErrorMessage("Generate Sample Data failed: <msg>")` (guard contract).

New module `src/ui/sampleDataAi.ts` holds the pure functions + orchestration
(`aiGenerateSampleData(deps)`) so `tableCommands.ts` stays thin and the logic is unit-testable.
`generateSampleInserts` (core/ddl/sampleData) stays exported/tested — only this command stops
using it (documented retention; removal is out of scope).


### F — keyword/`public` resolution for executed SQL

Planner-verified diagnosis: `splitStatements` (src/core/statementParser.ts) is literal-aware
and splits on `;` only — `FROM order` does NOT break the splitter, so the failure is Postgres
rejecting the unquoted reserved keyword.

**Exact rewrite rule (Round-1 review finding 2 — keyword-only)**: rewrite an identifier IFF
ALL of: unquoted AND unqualified AND follows FROM/INTO/UPDATE/JOIN AND
`isPgReservedKeyword(name)` AND `name ∈ listTables("public")`. Rewrite emits `"public".<name>`
(schema quoted, identifier quoted — a reserved keyword must be quoted in both positions to be
safe). EVERYTHING else is untouched — plain non-keyword unqualified tables keep search_path
semantics. CTE names shadow tables (never rewrite inside a `WITH x AS` where x shadows).

**search_path-collision safety**: with `search_path = sales, public` and a table `order` in
BOTH schemas, bare `FROM order` today errors at parse time (reserved keyword unquoted NEVER
resolves — pg rejects `order` as an identifier before name lookup, regardless of search_path).
So there is no today-behavior to preserve for keyword names; qualifying to `"public"."order"`
is strictly an improvement. The rule stays keyword-only precisely so that NON-keyword names
that legitimately resolve via search_path (`FROM users` → sales.users) are never retargeted.
Documented in TASK-007.

**Choke point (Round-1 review finding 1)**: the transform is applied in `runStatements` in
`src/extension.ts` (~L450 — the single submit path for editor `vsdb.runQuery` L433 AND CodeLens
`vsdb.runStatement` L447) and in the browse flow (`src/ui/browseCommands.ts`, wave 1). This
covers the reported editor-executed `SELECT * FROM order;` case. TASK-007 therefore owns
`src/extension.ts` + `src/extension.test.ts` (post-003) and adds a runStatement-path test.
Never inside the splitter. Executor first confirms the diagnosis with a live adapter run and
records findings in TASK-007 Discussion before implementing (stop-and-record if the server
already accepts the statement).

### G — Postman Payload

Right-click table/view/routine → `vsdb.postmanPayload` → clipboard gets a JS object literal:
`{ schema: "s", table: "name", <col>: this.workingObj.<col>, … }` — the key stays `table` for
all three kinds (user requirement).

**Column sources (decided)**: tables AND views → `adapter.listColumns(table, schema)`
(verified: postgres impl queries information_schema/pg_catalog by (schema, table) — views have
queryable columns there; no separate view-output introspection method exists). Routines → NEW
adapter method `listRoutineParams(schema, routine): Promise<Array<{ name: string | null;
dataType: string }>>` implemented ONLY on PostgresAdapter (pg_catalog `proargnames`/
`proallargtypes` via parameterized query, same pattern as listColumns); mysql/mssql adapters
throw `NotImplementedError` (existing contract pattern — command guards on driver anyway).

**JS literal shape (pure `buildPostmanPayload`)**: 2-space indented object literal; `schema` +
`table` string keys first; one line per column: `<key>: this.workingObj.<key>,`. Key quoting:
plain JS identifier (`/^[A-Za-z_$][A-Za-z0-9_$]*$/`) → bare key; anything else (spaces,
dashes, unicode, leading digit) → double-quoted key `"weird-col"` — the VALUE reference still
uses `this.workingObj[<quoted key>]` when the key is not a plain identifier, so the emitted JS
is always valid. Reserved JS words (e.g. `default`, `class`) are quoted too.
